# 小U Control Tower：交互与安全呈现

## 目标

状态面板让用户一眼分清“仿真结果”“只读数据”和“可执行性”。它是规划与安全信息的控制塔，不承担动作执行；代码中没有相机、串口、CAN、ROS2、子进程或机械臂控制接口。

## 信息层级

1. **顶栏**：当前模式与总状态。始终显示“仅呈现 / 无执行入口”，避免把界面上的策略预览误解为已经下发。
2. **左侧任务与安全门**：目标类别、置信度、坐标系、策略预览，以及四个独立安全门。缺任意门不能被绿色成功提示掩盖。
3. **中部阶段与阻断原因**：只显示当前阶段和可复制的具体阻断原因；不使用“异常”这种无法定位的问题描述。
4. **右侧六关节表**：每个关节单独显示查询结果、控制器 online、数据年龄和角度。`fresh_online` 才是硬件预览可用；`query_failed`、`offline_reported`、`stale`、`future_timestamp`、`freshness_unknown` 都必须保持黄色/红色语义。
5. **底部事件时间线**：按时间保存只读诊断、策略拒绝和配置变化，供导出 JSON，而不是只在弹窗中短暂显示错误。

## 可用交互

- 三个模式按钮仅切换**呈现语义**：仿真、只读硬件、硬件预览。它们不写入硬件配置，也不会开启任何设备。
- “加载状态 JSON”可导入仿真、离线回放或只读电机诊断；“演示阻断状态”固定展示 J5 过期、J6 offline 的典型故障；“导出当前诊断”只保存当前视图模型。
- 模式为硬件预览时，面板要求六关节均为新鲜在线且四个安全门为真；但 `hardware_motion=false` 仍是输出的不变量。真实执行必须在此界面之外经过独立授权与硬件安全层。

## 数据接口

输入是普通 JSON：`mode`、`target`、`yolo`、`phase`、`safety`、`joint_report.samples` 和可选 `events`。保存的 `motor_feedback_diagnostic.py` / `joint_status_probe.py` 输出也可直接加载，面板会识别其顶层 `samples` / `scans` 和 `read_only=true`。每条关节样本可含 `observed_at_monotonic_s`、`round_trip_ms` 和解码后的 `feedback`。没有单调时间戳的旧日志仍能显示，但明确标记为 `freshness_unknown`，绝不默认“即时”。

## 验证边界

该界面的单元测试覆盖 J5 stale、J6 offline、查询成功但陈旧、仿真可预览和非法模式拒绝。它不能替代真实显示器刷新率、相机延迟、树莓派 GPU/CPU 负载或硬件急停测试；这些都应在硬件回归阶段单独留证。
