## 1. 帧格式总览

```
┌──────┬─────┬─────┬─────┬───────────────────┬────────┬────────┬──────┐
│ 0xAA │ CMD │ LEN │ SEQ │    PAYLOAD 0~248B │ CRC_LO │ CRC_HI │ 0x55 │
└──────┴─────┴─────┴─────┴───────────────────┴────────┴────────┴──────┘
  1B     1B    1B    1B         0~248B          1B       1B      1B
  帧头   命令   长度   序号       负载数据         CRC低字节 CRC高字节 帧尾
```

| 字段 | 字节数 | 说明 |
|------|--------|------|
| `0xAA` | 1 | 帧起始定界符 |
| `CMD` | 1 | 命令/响应码 |
| `LEN` | 1 | Payload 长度 (0~248) |
| `SEQ` | 1 | 序列号 (上位机递增, MCU 回显) |
| `PAYLOAD` | 0~248 | 负载数据 (含字节转义) |
| `CRC_LO` | 1 | CRC-16/MODBUS 低字节 |
| `CRC_HI` | 1 | CRC-16/MODBUS 高字节 |
| `0x55` | 1 | 帧结束定界符 |

- **最大帧长**: 1 + 1 + 1 + 1 + 248 + 2 + 1 = 255 字节
- **CRC 计算范围**: CMD + LEN + SEQ + PAYLOAD (不含转义前原始值)
- **CRC 校验**: 接收方计算上述字段的 CRC-16/MODBUS, 与 `CRC_LO`/`CRC_HI` 比对
- **CRC 特殊值**: `0xFFFF` 可跳过 CRC 校验 (仅调试用, 生产环境禁用)

## 2. 字节转义规则

Payload 中以下字节需转义, 以区分帧边界:

```
原始字节  →  转义后
────────────────────
  0xAA    →  0xBB 0x0A
  0x55    →  0xBB 0x05
  0xBB    →  0xBB 0x0B
```

- CMD / LEN / SEQ 字段**不参与转义**
- CRC 字段**不参与转义**
- 帧头 `0xAA` 和帧尾 `0x55` **不参与转义** (它们是边界标记)

> **注意**: 发送方先转义再发送, 接收方先接收再解转义, 然后计算 CRC。

## 5. Payload 详解

### 5.1 CMD_TRAJ_POINT (0x50) — 单个轨迹点

```
Payload: 26 字节
┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│ J1 angle │ J2 angle │ J3 angle │ J4 angle │ J5 angle │ J6 angle │ duration │
│ float(4) │ float(4) │ float(4) │ float(4) │ float(4) │ float(4) │ uint16(2)│
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
  0~3        4~7        8~11       12~15      16~19      20~23       24~25
```

| 偏移 | 长度 | 类型 | 内容 | 范围 |
|------|------|------|------|------|
| 0 | 4 | float32 LE | 关节 1 角度 (°) | -170~170 |
| 4 | 4 | float32 LE | 关节 2 角度 (°) | -130~130 |
| 8 | 4 | float32 LE | 关节 3 角度 (°) | -140~140 |
| 12 | 4 | float32 LE | 关节 4 角度 (°) | -180~180 |
| 16 | 4 | float32 LE | 关节 5 角度 (°) | -90~90 |
| 20 | 4 | float32 LE | 关节 6 角度 (°) | -180~180 |
| 24 | 2 | uint16 LE | 运动时间 (ms) | 0~65535 |

- **所有浮点均为 IEEE 754 单精度, 小端序**
- 角度为**绝对角度**, 相对用户设定的零点
- MCU 安全层会自动限幅, 超出范围的值仍可发送但会被钳位

### 5.2 CMD_TRAJ_BATCH (0x53) — 批量轨迹点

```
Payload = N × 26 字节, N=1~9

┌──────────────────────────────────────────────────┐
│  TrajPoint[0]  │  TrajPoint[1]  │ ... │ TrajPoint[N-1] │
│     26B        │      26B       │     │      26B        │
└──────────────────────────────────────────────────┘
```

- 每个 26B 结构与 `CMD_TRAJ_POINT` 完全相同
- N 最大为 9 (PayLoad max 248 / 26 = 9.5 → 取整 9)
- 各点按顺序执行

**响应**:

```
RSP_TRAJ_ACK (0x81):
┌──────────────┐
│ buf_remaining│
│   uint8 (1B) │
└──────────────┘
```

- `buf_remaining`: 处理完当前批次后 MCU 缓冲区剩余槽位 (0~16)
- 初始缓冲区容量: **16 帧**

**示例 — 发送 3 个轨迹点 (78 字节 Payload):**

```
上位机 → MCU:
  AA 53 4E 01  [78 bytes payload]  CRC_LO CRC_HI  55

MCU → 上位机:
  AA 81 01 01  0D  CRC_LO CRC_HI  55
                 ↑
           buf_remaining = 13
```

### 5.3 CMD_GET_STATE (0x20) 响应

```
响应 Payload (56 字节):
┌───────┬───────┬───────┬───────┬────────────────────────────────────────────────┐
│ state │ err   │ estop │ motion│  Joint1~6: angle(4)+speed(4)+torque(4)+online(1)│
│ uint8 │ uint8 │ uint8 │ uint8 │                    6 × 13B = 78B               │
└───────┴───────┴───────┴───────┴────────────────────────────────────────────────┘
```

实际上响应 payload 中关节部分是压缩的，每个关节 13B:
| 偏移 | 内容 |
|------|------|
| 0 | angle (float, 4B) |
| 4 | speed (float, 4B) |
| 8 | torque (float, 4B) |
| 12 | online (uint8, 1B) |

### 5.4 CMD_STREAM_START (0x22)

```
Payload (2 字节):
┌──────────────┐
│  rate_ms     │
│ uint16 LE (2)│
└──────────────┘
```
- 遥测推送间隔, 单位 ms, 推荐 20~200
- MCU 每 `rate_ms` 主动推送一帧 `RSP_TELEMETRY (0x80)`

## 6. 轨迹批量传输协议

### 6.1 数据流

```
  Pi (ROS2)                          MCU (STM32)
     │                                   │
     │── CMD_TRAJ_POINT (26B) ──────────→│  入队到环形缓冲区
     │←── RSP_TRAJ_ACK [free] ───────────│  返回剩余槽位
     │                                   │
     │── CMD_TRAJ_BATCH (N×26B) ────────→│  N帧连续入队
     │←── RSP_TRAJ_ACK [free] ───────────│  返回剩余槽位
     │                                   │  joint_ctrl 线程逐帧执行
     │                                   │  每帧调用 set_angles(6轴)
     │                                   │
     │── CMD_TRAJ_BATCH ────────────────→│
     │←── RSP_TRAJ_OVERFLOW ────────────│  缓冲区满!
     │  (等待 50ms 后重试)               │
     │── CMD_TRAJ_BATCH ────────────────→│  重试成功
     │←── RSP_TRAJ_ACK [free] ──────────│
```

### 6.2 执行逻辑 (MCU 内部) — 闭环到位检测

1. 轨迹点存入 16 帧环形缓冲区
2. `joint_ctrl` 线程每 10ms (TRAJ_INTERPOLATION_MS) 检查一次:
   - 如果空闲且有未执行轨迹点 → 取出, 调用 `set_angles(joint_ids, angles, 60rpm, 100rpm/s, mode=1, count=6)`
   - `set_angles` 使用**梯形轨迹模式 (mode=1)**, 自动计算各关节同步时间
   - 等待 `duration_ms` (最小等待时间) 后, 进入**到位检测**
3. **闭环到位检测** (v4.1 新增):
   - 通过 CAN 自动回传的 `g_sys.joints[i].angle` 实时监测各关节角度
   - 所有在线关节角度误差 < **0.5°** (TRAJ_ARRIVAL_TOLERANCE) 时 → 立即加载下一个轨迹点
   - 若有关节未到位 → 继续等待, 每 10ms 重新检查
   - **超时保护**: 若 `3 × duration_ms` (最少 3 秒) 仍未到位 → 强制加载下一帧并打印警告
4. 离线关节自动跳过, 不参与到位判断
5. 所有关节同步运动, 同时到达目标角度

> **Pi 侧注意**: `duration_ms` 现在是**最小等待时间**, 而非精确的段时长。
> 实际段时长 = `max(duration_ms, 舵机实际到位时间)`。
> 建议 Pi 侧设置 `duration_ms` 略小于理论计算值, 让 MCU 的到位检测决定实际节奏。
> 若 debug 串口出现 `WARN: traj timeout` 说明 `duration_ms` 设置过短, 舵机无法在 3×duration 内到达。

### 6.3 运动模式

MCU 使用 DrEmpower 驱动的 **mode=1 (梯形轨迹模式)**:
- 各关节以不同速度运动, 保证**同时到达**各自目标位置
- `speed=60rpm`: 最快关节转速
- `param=100rpm/s`: 启停加转速

## 7. 流控机制

### 7.1 缓冲区容量

- 环形缓冲区: **16 帧**
- 每帧对应一个轨迹点 (6 关节角度 + 持续时间)

### 7.2 流控信号

每次轨迹命令的响应都携带 `buf_remaining`:

| 响应 | 含义 |
|------|------|
| `RSP_TRAJ_ACK` + free | 成功入队, free = 当前剩余槽位数 |
| `RSP_TRAJ_OVERFLOW` | 缓冲区满, 拒绝, 等 50ms 重试 |

### 7.3 Pi 侧推荐策略

```
Pseudocode:

MIN_BATCH = 2
LOW_WATERMARK  = 4   // 低于此值 → 暂停发送
HIGH_WATERMARK = 10  // 高于此值 → 恢复发送

send_batch(traj_points):
    for chunk in chunks(traj_points, max_per_batch):
        while True:
            remaining = my_tracker.estimated_free  // 由上次 ACK 更新
            if remaining <= LOW_WATERMARK:
                sleep(50ms)
                continue
            
            n = min(len(chunk), remaining, 9)  // 最多 9 帧/包
            batch = chunk[:n]
            ack = send_frame(CMD_TRAJ_BATCH, batch)
            
            if ack.code == RSP_TRAJ_ACK:
                my_tracker.estimated_free = ack.buf_remaining
                chunk = chunk[n:]
                break
            elif ack.code == RSP_TRAJ_OVERFLOW:
                sleep(50ms)  // 重试
```

## 9. CRC 算法

**CRC-16/MODBUS**, 多项式 `0x8005`, 初始值 `0xFFFF`, 无输出异或。

```python
# Python 参考实现
CRC16_TABLE = [
    0x0000, 0xC0C1, 0xC181, 0x0140, 0xC301, 0x03C0, 0x0280, 0xC241,
    # ... (256 entries, see comm_protocol.c for full table)
]

def crc16(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc = (crc >> 8) ^ CRC16_TABLE[(crc ^ b) & 0xFF]
    return crc
```

**CRC 计算范围**: `CMD + LEN + SEQ + PAYLOAD` (解转义后的原始值, 不含帧头帧尾)

```python
# 构建帧示例
def build_frame(cmd: int, seq: int, payload: bytes) -> bytes:
    assert len(payload) <= 248
    
    # CRC over [CMD, LEN, SEQ, PAYLOAD]
    crc_data = bytes([cmd, len(payload), seq]) + payload
    crc = crc16(crc_data)
    
    # 组装原始帧
    raw = bytes([0xAA, cmd, len(payload), seq])
    raw += escape_payload(payload)  # 字节转义
    raw += bytes([crc & 0xFF, (crc >> 8) & 0xFF])
    raw += bytes([0x55])
    return raw
```

完整 CRC 查找表见 `Src/comm_protocol.c`。

### 10.2 帧解析伪代码

```python
class ProtoParser:
    STATE_WAIT_START = 0
    STATE_CMD = 1
    STATE_LEN = 2
    STATE_SEQ = 3
    STATE_PAYLOAD = 4
    STATE_CRC1 = 5
    STATE_CRC2 = 6
    STATE_WAIT_END = 7
    
    def __init__(self):
        self.state = self.STATE_WAIT_START
        self.rx_buf = bytearray()
        self.escape_next = False
        self.crc_calc = 0xFFFF
    
    def feed(self, byte: int):
        self.rx_buf.append(byte)
    
    def try_parse(self):
        """遍历 rx_buf, 尝试提取完整帧. 返回 Frame 或 None."""
        while len(self.rx_buf) > 0:
            ch = self.rx_buf.pop(0)
            
            if self.state == self.STATE_WAIT_START:
                if ch == 0xAA:
                    self.state = self.STATE_CMD
                    self.payload = bytearray()
                    self.escape_next = False
            
            elif self.state == self.STATE_CMD:
                self.cmd = ch
                self.crc_calc = crc16_update(0xFFFF, ch)
                self.state = self.STATE_LEN
            
            elif self.state == self.STATE_LEN:
                self.payload_len = ch
                if self.payload_len > 248:
                    self.state = self.STATE_WAIT_START  # 非法, 丢弃
                else:
                    self.crc_calc = crc16_update(self.crc_calc, ch)
                    self.state = self.STATE_SEQ
            
            elif self.state == self.STATE_SEQ:
                self.seq = ch
                self.crc_calc = crc16_update(self.crc_calc, ch)
                self.state = self.STATE_PAYLOAD if self.payload_len > 0 else self.STATE_CRC1
            
            elif self.state == self.STATE_PAYLOAD:
                # 字节解转义
                if self.escape_next:
                    self.escape_next = False
                    if ch == 0x0A: ch = 0xAA
                    elif ch == 0x05: ch = 0x55
                    elif ch == 0x0B: ch = 0xBB
                elif ch == 0xBB:
                    self.escape_next = True
                    continue
                
                self.payload.append(ch)
                self.crc_calc = crc16_update(self.crc_calc, ch)
                
                if len(self.payload) >= self.payload_len:
                    self.state = self.STATE_CRC1
            
            elif self.state == self.STATE_CRC1:
                self.crc = ch
                self.state = self.STATE_CRC2
            
            elif self.state == self.STATE_CRC2:
                self.crc |= (ch << 8)
                self.state = self.STATE_WAIT_END
            
            elif self.state == self.STATE_WAIT_END:
                if ch == 0x55:
                    # valid frame
                    if self.crc == 0xFFFF or self.crc_calc == self.crc:
                        return Frame(self.cmd, self.seq, bytes(self.payload))
                self.state = self.STATE_WAIT_START
        
        return None
```

### 10.3 批量轨迹发送示例

```python
def send_trajectory_batch(ser, parser, points, seq):
    """
    points: list of (j1, j2, j3, j4, j5, j6, duration_ms)
    每批最多 9 个点
    """
    import struct
    
    MAX_PER_BATCH = 9
    LOW_WATER = 4
    free_slots = 16  # 初始假设全部空闲
    
    offset = 0
    while offset < len(points):
        # 流控: 等待缓冲区有空间
        while free_slots <= LOW_WATER:
            # 可以在这里读取遥测帧来更新 free_slots
            # 或者简单 sleep 等待 MCU 消耗
            time.sleep(0.05)
            free_slots += 1  # 保守估计
        
        # 确定本批发多少
        n = min(len(points) - offset, MAX_PER_BATCH, free_slots)
        batch = points[offset:offset+n]
        
        # 构建 payload
        payload = b''
        for p in batch:
            payload += struct.pack('<ffffffH', *p)
        
        # 发送 CMD_TRAJ_BATCH
        frame = build_frame(0x53, seq, payload)
        ser.write(frame)
        
        # 等待响应
        resp = wait_response(ser, parser, timeout=1.0)
        if resp and resp.cmd == 0x81:  # RSP_TRAJ_ACK
            free_slots = resp.payload[0]
            offset += n
            seq = (seq + 1) & 0xFF
        elif resp and resp.cmd == 0x82:  # RSP_TRAJ_OVERFLOW
            time.sleep(0.05)  # 重试
        else:
            # 超时或错误, 重试
            time.sleep(0.1)
```

### 10.4 典型运动流程

```python
def exec_trajectory(ser, parser, waypoints):
    """waypoints: ROS2 规划好的轨迹点列表"""
    
    # step 1: 清空 MCU 缓冲区
    send_cmd(ser, 0x51, b'')  # CMD_TRAJ_BUFFER_CLEAR
    ack = wait_response(ser, parser)
    free = ack.payload[0] if ack else 16
    
    # step 2: 批量发送所有轨迹点
    send_trajectory_batch(ser, parser, waypoints, seq=0)
    
    # step 3: 可选, 开启遥测监控运动进度
    send_cmd(ser, 0x22, struct.pack('<H', 50))  # CMD_STREAM_START, 50ms
```

## 11. 错误处理

### 11.1 常见响应码含义

| 响应码 | 含义 | 建议处理 |
|--------|------|----------|
| `0x00` (ACK) | 成功 | 正常继续 |
| `0x81` (TRAJ_ACK) | 轨迹入队成功 | 检查 `buf_remaining`, 决定是否继续发送 |
| `0x82` (TRAJ_OVERFLOW) | 缓冲区满 | `sleep(0.05)`, 重试 |
| `0x03` (ESTOP_ACTIVE) | 系统急停中 | 发送 `CMD_CLEAR_ERROR` |
| `0x04` (INVALID_PARAM) | Payload 长度错误 | 检查数据格式 |
| 超时无响应 | MCU 忙或通信故障 | 重试 3 次, 每次间隔 200ms |

### 11.2 MCU 端安全保护

- **关节限位**: 超出硬件限位的角度会被自动钳位
- **急停触发条件**:
  - CAN 通信超时 (>50ms)
  - 关节过流 (>8A)
  - 关节过热 (>80°C)
  - 关节离线检测
- **零点保护**: 零点异常时拒绝执行运动指令
