# 树莓派 / F407 分阶段联调清单

本清单只适用于 `transport-only` F407 基线。当前目标是证明通信链路和安全锁有效，不是让机械臂运动。

## A. 上传前 Windows 离线检查

在 `D:\机械臂\work\raspi_robot_ai_safety_20260808` 运行：

```powershell
python -m compileall -q robot_ai tests tools
python -m unittest discover -s tests -v
python tools/verify_six_axis_stack.py
```

这些命令不打开树莓派串口、不连接 CAN、不发送运动。确认 `hardware_calibration.json` 中 `motion_enabled` 和所有硬件确认项仍为 `false`。

## B. Pi 上的离线校验

上传完成后，在 Pi 终端运行：

```bash
cd /home/pi/raspi_robot_ai
python3 -m compileall -q robot_ai tests tools
python3 -m unittest discover -s tests -v
python3 tools/verify_six_axis_stack.py
```

此阶段不需要连接 F407，也不会打开 `/dev/serial0`。

## C. 断电接线检查

在 F407 和 Pi 都断电时完成：

| 检查 | 要求 |
|---|---|
| TX/RX | Pi GPIO14/TXD -> F407 PA10；Pi GPIO15/RXD <- F407 PA9 |
| GND | Pi 与 F407 共地 |
| 电平 | 仅 3.3 V TTL；UART 引脚不能接 5 V |
| 电源 | UART 不作为供电线；电机电源、CAN、夹爪 PWM 不参与本阶段 |
| 急停 | 未实测即保持实机动作门锁定 |

刷入 F407 前确认 Keil 构建日志与串口启动日志都显示 `CAN/PWM not initialized` 或等价信息。

## D. 单纯 UART 收发

在已刷入安全基线且接线复核完成后，Pi 上仅发送 PING：

```bash
cd /home/pi/raspi_robot_ai
python3 robot_ai/arm_control/uart_protocol.py --ping --port /dev/serial0 --baud 115200 --sequence 1
```

期望 ACK：`AA 00 00 01 B0 00 55`。超时、乱码、非 ACK 都停止排查接线、波特率和固件，不进行任何动作测试。

## E. J1..J6 默认离线帧检查

以下命令只打印六轴帧，默认不会打开 `/dev/serial0`：

```bash
python3 robot_ai/arm_control/joint_uart_staged_test.py --joint 1 --target-deg 0 --duration-ms 1500
python3 robot_ai/arm_control/joint_uart_staged_test.py --joint 2 --target-deg 0 --duration-ms 1500
python3 robot_ai/arm_control/joint_uart_staged_test.py --joint 3 --target-deg 0 --duration-ms 1500
python3 robot_ai/arm_control/joint_uart_staged_test.py --joint 4 --target-deg 0 --duration-ms 1500
python3 robot_ai/arm_control/joint_uart_staged_test.py --joint 5 --target-deg 0 --duration-ms 1500
python3 robot_ai/arm_control/joint_uart_staged_test.py --joint 6 --target-deg 0 --duration-ms 1500
```

每条应显示一个 26 字节 `<6fH>` payload，只有选中的一个 J 字段非零（此处为 0 时六轴都为 0），并明确写出 `no serial device is opened`。

## F. 锁定帧回传检查

只有在步骤 D 的 PING 成功、且 `GET_STATE` 显示 `state=0x05` 与 `error=0x0C` 时，才可逐轴验证 F407 对合法轨迹帧的拒绝。示例 J1：

```bash
python3 robot_ai/arm_control/joint_uart_staged_test.py --joint 1 --target-deg 0 --duration-ms 1500 --probe-locked --confirm LOCKED-J1
```

依次把 `1` 和 `LOCKED-J1` 替换为 `2..6` / `LOCKED-J2..LOCKED-J6`。工具会先读 F407 状态；只在确认固件处于安全锁时发送一帧，并要求返回 `RSP_MOTION_LOCKED (0x06)` 加原命令字节 `50`。这不是运动测试。

## G. 不进入的阶段

当前不要使用 `--execute`。它只能在新的硬件使能固件完成独立评审后使用，并要求下列每项已经实测并写入配置：

- J1..J6 CAN 节点 ID、编码器零位、方向、最小/最大限位、速度和加速度。
- F407 已刷入经过审查的硬件使能版本，不是当前 transport-only 版本。
- 物理急停的逻辑、电机断电路径和恢复流程已经实测。
- F407 反馈、UART 收发和 CAN 实测速率已确认。
- 有人监护、低速、单轴、无负载，并有明确的本次动作授权。

未完成零位与方向测量时，不能从“软件限位”推导出可安全运动的范围。限位值必须相对已确认的零位和实际正负方向记录。
