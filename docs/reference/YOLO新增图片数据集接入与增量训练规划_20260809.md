# YOLO 新增图片数据集接入与增量训练规划

## 目标

后续图片不直接复制进当前 train/val 目录。每批数据先完成只读审计、去重、类别版本确认和独立验证集冻结，再进入训练。当前生产模型继续使用四类 v1；新增 `cup/tissue` 时切换到 v2，必须重建检测头并重新训练，不能静默复用四类编号。

## 接入目录合同

推荐每批数据使用独立目录：

```text
incoming/<batch_name>/
  images/
    *.jpg|*.png|*.webp
  labels/                 # 未标注批次可以暂时没有
    *.txt                 # 与图片同名的 YOLO 标签
  metadata.json           # 可选：相机、光照、距离、场景、采集日期
```

YOLO 标签仍为 `class_id cx cy width height`，坐标归一化到 `[0,1]`。图片和标签可以包含相同的子目录层级。

## 类别版本

- v1：`0=pen, 1=bottle, 2=cola, 3=earphone`，与当前部署模型兼容。
- v2 草案：保留 v1 编号，新增 `4=cup, 5=tissue`。
- `cup` 不能临时标成 `bottle`，`tissue` 不能临时标成 `earphone`。
- `desktop_item` 是任务/策略概念，不应在没有明确视觉定义时变成一个包罗万象的检测类别。
- 如果后续还要增加类别，创建 v3，不修改旧版本含义。

配置文件：

- `robot_ai/vision/config/yolo_class_schema_v1.json`
- `robot_ai/vision/config/yolo_class_schema_v2_draft.json`

## 收到数据后的第一条命令

未标注图片：

```powershell
& D:\机械臂\.venv_transformer_gpu\Scripts\python.exe tools/inspect_yolo_dataset_intake.py `
  --source "D:\待接入数据\batch_001" `
  --schema robot_ai/vision/config/yolo_class_schema_v2_draft.json `
  --batch-name batch_001 `
  --mode unlabeled `
  --compare-images my_all_data/images,runtime/yolo_train/xiaou_objects_dataset_deep/images `
  --output runtime/yolo_intake/batch_001_unlabeled.json
```

已经完成 YOLO 标注的数据：

```powershell
& D:\机械臂\.venv_transformer_gpu\Scripts\python.exe tools/inspect_yolo_dataset_intake.py `
  --source "D:\待接入数据\batch_001" `
  --schema robot_ai/vision/config/yolo_class_schema_v2_draft.json `
  --batch-name batch_001 `
  --mode labeled `
  --compare-images my_all_data/images,runtime/yolo_train/xiaou_objects_dataset_deep/images `
  --output runtime/yolo_intake/batch_001_labeled.json
```

接口会检查：图片是否可读、标签是否一一对应、类别 ID 是否越界、框是否合法、分辨率分布、类别实例数、批内重复和与历史数据重复。它只写审计 JSON，不修改原始数据。

## 数据量与采集重点

对于新类别 `cup/tissue`，初始目标为每类至少 200 张已标注训练图片和 40 张真正独立的验证图片。优先覆盖：

- 明亮、昏暗、逆光和阴影；
- 不同桌面背景、距离、角度和相机曝光；
- 单目标、多目标、遮挡和画面边缘；
- 杯把可见/不可见、透明杯/不透明杯；
- 纸巾盒、抽出纸巾、纸巾边缘和重叠纸巾；
- 易混淆负样本，例如瓶子与杯子、白色纸张与纸巾。

同一段视频的相邻帧不能随机拆到 train 和 val；应按采集会话分组，防止数据泄漏。

## 训练决策

1. 只增加 v1 四类图片：可从当前 deep 模型做低学习率增量微调，同时保留旧数据回放，避免灾难性遗忘。
2. 增加 `cup/tissue`：使用 v2 六类 YAML，重新建立六类检测头并在旧四类 + 新两类的合并数据上训练。
3. 每次训练至少保留：基线、候选权重、数据清单、类别分布、随机种子、GPU 配置、mAP、Precision/Recall、ONNX CPU 延迟和光照/模糊回归。
4. 只有标准验证和鲁棒性验证达到预设门限才生成部署候选；候选不会自动覆盖生产模型。
5. 树莓派部署前必须成对携带 `.onnx + .names`，并做解包后的类别检查。

## 与 Transformer 的接口

YOLO 输出使用稳定字段：

```json
{
  "schema_version": 2,
  "class_id": 4,
  "class_name": "cup",
  "confidence": 0.91,
  "bbox_xyxy": [120, 80, 260, 330],
  "center_px": [190, 205],
  "frame_width": 640,
  "frame_height": 480,
  "capture_timestamp_s": 0.0,
  "model_version": "xiaou_objects_v2_candidate"
}
```

进入 Transformer/ROS2 前还必须补齐相机标定、坐标变换、检测新鲜度和安全状态。未知类别、低置信度、过期检测或没有标定时只允许返回 `reject/abort`，不生成真实运动。

## 当前接口验证

已用现有 deep 数据集对 `inspect_yolo_dataset_intake.py` 做烟测：100 张图片、100 个标签、缺失 0、错误 0、重复组 0，`training_ready=true`。
