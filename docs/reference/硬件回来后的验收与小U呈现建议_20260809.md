# 硬件回来后的验收与小U呈现建议

这份清单承接离线回归结果。硬件回来后仍必须按阶段推进，不能因为离线仿真通过就直接打开运动门。

## 硬件验收顺序

### 0. 上电前

- 保存当前 Pi 版本、`hardware_calibration.json`、F407 固件版本和 SHA-256。
- 电机电源、夹爪电源和 CAN 收发器保持断开；急停按钮可触达。
- 确认 `motion_enabled=false`、`hardware_ready=false`，并运行：

```bash
python3 tools/protocol_offline_replay.py
python3 tools/ros2_offline_replay.py --checkpoint runtime/decision/transformer_policy_deep.int8.onnx
```

### 1. UART 只读

- 先 `CMD_PING`，再 `CMD_GET_STATE`，最后逐个 `CMD_GET_JOINT`。
- 每个关节至少采集 20 个带时间戳样本；J5/J6 的新鲜度阈值先用 500 ms，不能只看 `online` 位。
- 记录丢帧、CRC 错误、序号回退、响应延迟和 F407 状态码。
- 任一关节超时、状态异常或序号不连续，停止进入 CAN 阶段。

### 2. CAN 被动监听

- 只接收，不发送命令；确认实际 bitrate、J1..J6 节点 ID、反馈周期和错误帧。
- 对照 `can_protocol.py` 解码位置、速度、状态位、fault、E-stop、heartbeat。
- 现场 bitrate 若与配置不一致，先更新协议记录并重新审查，不能猜测。

### 3. 标定与安全门

- F407 保存零位、方向、软限位和校准记录 CRC；Pi 只核验版本和 CRC。
- 逐关节确认正方向、编码器零位、最小/最大限位、速度/加速度。
- 急停必须切断执行链路，并在 ROS2 `/xiaou/hardware_ready` 上保持 false 直到全部通过。

### 4. 单轴低风险运动

- 仅在有人看守、急停可触达、机械限位已确认时进行。
- 先 J1，再 J2/J3，再腕部 J4/J5/J6；每次只移动很小角度。
- 每一步都检查目标角、反馈角、方向、速度、超时和急停响应。

### 5. 相机与抓取

- 先做棋盘格/Charuco 和桌面单应性，确认 `base_link` 坐标方向。
- 用 CPU ONNX YOLO 先验证类别、框中心和延迟，再启用 Transformer 候选。
- 每类物品先做空夹爪、低速、低高度的单次取放，再做连续回归。
- 纸巾必须使用拉取策略，不能把纸巾堆当刚体抬起。

## 小U的高级呈现与易用性建议

### 视觉层

- 主界面只保留一个清晰的“当前状态”：观察、准备、接近、抓取、抬升、放置、阻断。
- 用真实相机画面作为主区域，叠加检测框、目标中心、`base_link` 目标点和当前 TF，不要堆装饰卡片。
- 侧边显示六关节在线/新鲜度、夹爪开度、风险值和最近一次阻断原因；J5/J6 直接显示“数据年龄”。
- 运动被安全门阻断时使用醒目的红色状态条和具体原因，不显示模糊的“AI 正在思考”。

### 交互层

- 常用操作使用图标按钮：急停、暂停、回零、重新检测、保存日志；悬停提供明确提示。
- “仿真 / 只读硬件 / 低速实机”使用分段控件，切换到实机要求二次确认和硬件就绪摘要。
- 抓取流程提供“预览轨迹”按钮，先显示目标姿态、夹爪宽度、风险和预计时间，再允许执行。
- 所有失败都可一键导出 JSON/日志，便于复盘，不把失败状态自动重试成不可控动作。

### 架构层

- YOLO 只负责检测，Transformer 只负责策略，MoveIt 负责 IK/碰撞/轨迹，F407 负责底层反馈和最后的运动锁。
- 小U的表情可以作为状态反馈，但不能替代数值状态、急停和错误原因。
- 默认启动为离线仿真或只读；真正的运动权限必须由配置、ROS2 安全门和 F407 三方同时确认。

## 不应宣称的内容

- 离线 `48/48` 通过不等于真实抓取成功率。
- 没有真实水杯标注时，不应宣称 YOLO 已学会水杯。
- 没有编码器、夹爪力和相机标定实测时，不应宣称机械臂已经完成闭环控制。
