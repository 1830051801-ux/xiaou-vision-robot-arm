# F407 / Keil：J6 反馈链路改造说明

版本：2026-08-11  
适用固件基线：`stm32_firmware_f407_vla_uart_20260807/BasicSetting_DaRanRobot`  
范围：仅修复 **J6 CAN 状态反馈进入 F407 缓存并正确上报给树莓派** 的链路；不启用运动、不改零位、不改电机参数、不改 CAN ID。

## 1. 已确认的现场证据

树莓派在 `115200 8N1` 下使用只读 `CMD_PING (0x01)` 与 `CMD_GET_JOINT (0x21)` 完成了一次 8 轮六轴采样：

| 项目 | 实测结论 |
| --- | --- |
| Pi → F407 传输 | 53 次请求中 51 次有响应；成功响应 P50 约 24.9 ms、P95 约 25.1 ms；无序列号错配 |
| J1、J2、J3、J5 | 8/8 查询成功且全程 `online=true`，角度/速度/力矩均有合理非零反馈 |
| J4 | 7/8 查询成功；有一次 305.8 ms 超时，下一轮立即恢复在线，暂不足以判定为 J4 硬件故障 |
| J6 | 8/8 UART 查询都有 ACK，但每次均为 `angle=0, speed=0, torque=0, online=false` |

结论：**Pi UART、F407 协议解析和 J1–J5 的反馈缓存均在工作；J6 没有进入有效反馈缓存。**

这不能直接证明“J6 电机损坏”。根因仍可能是 J6 驱动未上电、节点 ID 不为 6、J6 没有打开状态流、J6 帧没有到 CAN1、状态帧被共享接收缓冲覆盖，或 F407 没有把 J6 帧写入 `g_sys`。

## 2. 必须保持的兼容与安全边界

### 2.1 不得改变现有 Pi 协议

保留以下命令、响应码和字节布局：

| 项目 | 固定值 |
| --- | --- |
| 帧 | `[AA][CMD][LEN][SEQ][PAYLOAD][CRC16-MODBUS LE][55]`，含原有转义 |
| `CMD_GET_JOINT` | `0x21`，请求 payload 为 1 字节 `joint_id`，有效范围 `1..6` |
| 查询响应 | `RSP_ACK=0x00`，payload 长度必须为 14 字节：`u8 joint_id + f32_le angle_deg + f32_le speed_rpm + f32_le torque_nm + u8 online` |
| J6 节点 | `CAN_ID_JOINT_6 = 6`，见 `Inc/arm_config.h` |
| 查询语义 | `online` 仅表示 F407 已收到该轴的**新鲜且有效**反馈；`online=false` 时树莓派不得视为可运动 |

不得为了诊断而改 `CMD_GET_JOINT` 的长度、字段顺序或把 `online=false` 伪装成在线。新增诊断信息只能使用新的版本化命令，不能塞进现有 14 字节响应。

### 2.2 不得为了得到反馈而打开运动

`Inc/arm_config.h` 的 `ARM_ACTUATOR_COMMANDS_ENABLED` 和物理急停门保持现状。允许把“只读 CAN 反馈监视”独立出来，但不得因此允许轨迹、位置、力矩、使能、零位或参数写入。

## 3. 当前源码链路与关键风险

现有基线中：

1. `Src/app_threads.c` 的 `joint_data_thread_entry()` 为 ID 1..6 调用 `enable_angle_speed_torque_state(id)` 与 `set_state_feedback_rate_ms(id, JOINT_FEEDBACK_RATE_MS)`，再循环调用 `angle_speed_torque_state_fresh()`。
2. `Device/src/DrEmpower_can.c` 的 `angle_speed_torque_state_fresh()` 共用全局 `rx_buffer`、`can_id`、`READ_FLAG`；它清零 `READ_FLAG` 后调用 `receive_data()`。
3. `receive_data()` 最多等待 10 ms；当前实现对每个关节最多等两次。任何不属于当前轮询轴的帧会被跳过，而全局缓冲又可能被下一帧覆盖。
4. 只有拿到匹配帧时，`joint_data_thread_entry()` 才更新 `g_sys.joints[i]` 与 `g_sys.joint_online[i]`。
5. `CMD_GET_JOINT` 的实现只读取 `g_sys.joints[joint_index]` 和 `g_sys.joint_online[joint_index]`，**不直接访问 CAN**。

因此，现场的 J6 全零离线表示：J6 缓存从未被有效刷新或已被判为离线；不能靠加大树莓派 UART 超时解决。

另外，已检查源码快照中 `ARM_ACTUATOR_COMMANDS_ENABLED` 默认是 `0`，而 `joint_data_thread` 的启动也位于该编译开关内。现场 J1–J5 已经有实时反馈，说明实际烧录固件或 Keil 宏配置可能与此快照不同。**改动前必须记录实际 Keil 工程、宏定义、生成的 `.axf/.bin` 哈希，不能把本快照当成已烧录二进制。**

## 4. 改造目标

### 必须达到

- J6 的有效状态帧一到达 CAN1，就独立写入 J6 缓存和接收时间；不能等 UART 查询才读 CAN。
- J1–J6 各自有独立接收缓存、接收时间和计数器；J6 丢帧不得覆盖 J1–J5 的状态。
- `CMD_GET_JOINT` 只复制 F407 快照并立即回包；正常响应目标小于 50 ms，验收上限 100 ms。
- J6 状态帧停止超过 `ARM_CAN_TIMEOUT_MS`（当前 200 ms）后，`online=false`；保留最近一次有效测量值用于诊断，但绝不因旧值而保持在线。
- 反馈监视可在“执行器命令锁定”状态运行；运动命令仍必须被现有安全门拒绝。

### 不在本次范围内

- 不给 J6 发使能、位置、速度、力矩、清错、设零、改 ID 或改反馈周期命令。
- 不修改机械结构、零位、方向、限位或控制参数。
- 不仅因为“J6 在线”就解除真实机械臂的运动安全门。

## 5. 建议的 Keil 改造步骤

### A. 先做无写入定位

1. 在 `HAL_CAN_RxFifo0MsgPendingCallback()` 处记录原始标准帧 ID、DLC、数据和到达计数；确认能否看到 ID 解码为 6 的状态帧。
2. 在 `joint_data_thread_entry()` 的 J6 分支处记录：
   - 是否运行到 `enable_angle_speed_torque_state(6)`；
   - 是否运行到 `set_state_feedback_rate_ms(6, JOINT_FEEDBACK_RATE_MS)`；
   - `angle_speed_torque_state_fresh(6, &ast)` 的成功/失败计数；
   - 最近收到的原始 CAN ID 与距离当前的毫秒数。
3. 不发任何写入型 CAN 命令。若 J6 物理状态流本来未开启，应先确认驱动配置与接线，再由硬件负责人授权处理。

### B. 用每轴缓存取代“轮询时抢一个共享缓冲”

在 F407 中新增内部只读缓存（名称可按工程规范调整）：

```c
struct joint_rx_cache {
    uint8_t  raw[8];
    uint8_t  dlc;
    uint8_t  valid;
    uint32_t last_rx_tick;
    uint32_t rx_count;
    uint32_t reject_count;
};

static struct joint_rx_cache g_joint_rx[MAX_JOINT_COUNT];
```

在 CAN RX ISR 中仅做短操作：读取帧、由**现有且已验证的驱动协议规则**识别状态帧、按关节 ID (`1..6`) 复制到 `g_joint_rx[id-1]`、更新 `last_rx_tick/rx_count`，再释放信号量。不要在 ISR 里等待信号量、打印日志、发送 CAN 或调用阻塞函数。

> 注意：不要仅凭“ID 解出 6”就把所有 J6 帧当作角度/速度/力矩帧。必须复用现有 `angle_speed_torque_state_fresh()` 已验证的状态帧识别规则，或在台架抓包后明确写出状态帧的低 5 位命令码与 DLC。

`joint_data_thread_entry()` 改为读取对应轴的缓存副本并在任务上下文解码，流程如下：

```c
/* 伪代码：不改变现有 Pi UART 协议 */
for (int index = 0; index < MAX_JOINT_COUNT; ++index) {
    uint8_t id = CAN_ID_JOINT_1 + index;
    struct joint_rx_cache snapshot;

    copy_joint_cache_atomically(index, &snapshot);
    if (!snapshot.valid ||
        rt_tick_get() - snapshot.last_rx_tick > rt_tick_from_millisecond(ARM_CAN_TIMEOUT_MS)) {
        set_joint_online(index, 0);
        continue;
    }
    if (!decode_verified_ast_state(snapshot.raw, snapshot.dlc, &ast)) {
        increment_reject_counter(index);
        set_joint_online(index, 0);
        continue;
    }
    update_g_sys_joint(index, id, ast.angle, ast.speed, ast.torque, 1);
}
```

缓存拷贝与 `g_sys` 更新必须使用短临界区、互斥量或序号锁，确保 UART 查询不会取到角度、速度、力矩来自不同帧的拼接数据。

### C. 把只读反馈线程与运动线程解耦

当前快照把 `joint_data_thread` 的启动放在 `#if ARM_ACTUATOR_COMMANDS_ENABLED` 内。应拆分为：

- `ARM_FEEDBACK_MONITOR_ENABLED=1`：仅允许 CAN RX、状态缓存、`CMD_PING`、`CMD_GET_STATE`、`CMD_GET_JOINT`；
- `ARM_ACTUATOR_COMMANDS_ENABLED=0`：继续拒绝所有会使机械臂运动或改变驱动状态的命令。

不得用 `ARM_ACTUATOR_COMMANDS_ENABLED=1` 作为“让 J6 有反馈”的捷径。

### D. 让 UART 查询只读快照并保持协议兼容

`Src/app_threads.c` 的 `CMD_GET_JOINT` 已经是从 `g_sys` 打包 14 字节响应的正确方向。改造时：

1. 在短临界区复制 `g_sys.joints[joint_index]` 与 `g_sys.joint_online[joint_index]` 到局部变量；
2. 释放锁后按原 14 字节布局打包；
3. 禁止在该 case 内调用 `receive_data()`、`read_property()`、`get_angle()`、`set_*()` 或等待 CAN；
4. 无新鲜 J6 帧时正常回 `RSP_ACK`，但 `online=0`。这是诊断需要的明确状态，不是 UART 错误。

## 6. 建议增加的只读可观测性

第一阶段不用改 Pi 协议即可在 Keil 调试器/RTT 打印以下指标：

- `J6 rx_count`、`J6 reject_count`、`J6 last_rx_age_ms`；
- 最近原始标准帧 ID 与 DLC；
- J6 状态流启用请求是否执行；
- 六轴缓存 `valid` 位和在线位。

若需要树莓派长期读取这些原因码，第二阶段再经协议评审新增独立的 `CMD_GET_JOINT_DIAG`。不得占用命令码或定义 payload，直到完整检查 `comm_protocol.h`、树莓派解析器和所有现有固件分支后完成版本协商。

## 7. 无运动验收清单

### 固件侧

- [ ] 编译时 `ARM_ACTUATOR_COMMANDS_ENABLED` 仍为 `0`，物理急停门未被绕过。
- [ ] CAN RX 日志/计数显示 J6 的有效状态帧实际到达，或能明确显示未到达。
- [ ] J6 帧到达后，J6 缓存的 `valid=1`、`last_rx_tick` 更新、`g_sys.joint_online[5]=1`。
- [ ] 停止 J6 状态帧超过 200 ms 后，J6 自动 `online=0`，且无运动命令发出。
- [ ] J6 缺失不会阻塞 J1–J5 缓存更新，也不会让 `CMD_GET_JOINT` 阻塞数秒。

### 树莓派侧（只读）

固件烧录并等待状态流稳定后运行：

```bash
cd /home/pi/raspi_robot_ai_safety_20260808
python3 robot_ai/arm_control/motor_feedback_diagnostic.py \
  --port /dev/serial0 --baud 115200 --startup-wait-s 10 --timeout-s 0.3 \
  --ping-count 5 --samples-per-joint 20 --joint-ids 1,2,3,4,5,6 \
  --interval-s 0.1 --freshness-threshold-s 3 \
  --fast-response-threshold-ms 100 --max-p95-latency-ms 100 --strict
```

验收通过条件：

- PING 5/5 成功；
- 每轴 20/20 查询成功，响应序列号一致；
- J1–J6 均 `online=true`；
- 所有轴 P95 响应小于等于 100 ms；
- J6 反馈值可以为物理零位，但必须来自有效新鲜状态帧，不能再是“全程固定 0 + `online=false`”；
- 命令仍只包含 `CMD_PING` 与 `CMD_GET_JOINT`，机械臂不运动。

## 8. 回退规则

若改造后 J1–J5 也掉线、CAN IRQ 溢出、UART 响应变慢或运动门状态发生变化：立即恢复改动前固件，不要在现场继续修改 J6 ID、零位或运动参数。保留 CAN 原始帧计数、Keil 宏配置、固件哈希和树莓派 JSON 报告，再离线定位。
