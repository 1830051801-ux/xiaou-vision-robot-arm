# 小U离线回归与界面决策

## 本轮离线结论

- MuJoCo 随机化回归：2 个独立种子、6 类场景、每类 4 次，共 48/48 通过。覆盖瓶子、水杯、笔、桌面物、纸巾抽取代理和可乐；位置、偏航和每个种子的场景尺寸做了有限扰动。无串口、CAN 或 ROS 硬件启动。
- 每次回归都检查 IK 收敛、轨迹点、假定关节限位、禁碰撞、抓取接触和释放后的桌面接触；纸巾仍是刚性叠层代理，不代表布料动力学。
- YOLO 深训生产候选仍是四类 `pen/bottle/cola/earphone`，120 epoch 的最佳 `mAP50=0.97009`、`mAP50-95=0.52897`；强增强轨迹最佳 `mAP50=0.90308`，保守增强轨迹最佳 `0.96539`，两者都暂不替换生产候选。当前数据没有真实 `cup` 或 `tissue` 标注，不能宣称已训练这两类。
- 数据检查移除了 `pen_calib_028.txt` 的零宽退化框，并把零宽/零高框改为准备阶段硬错误；清洗后的 train/val 共 100 张图、292 个实例，未发现孤立标签或不可读图片。
- YOLO 深模型 ONNX 约 12.24 MB；固定 OpenCV 单线程后，本轮 CPU 60 个样本的 mean/p50/p95 为 174.6/163.6/209.9 ms，四类均有输出。此前同配置复跑为 164.4/159.5/207.6 ms，说明延迟受 CPU 负载影响；Pi 上线前仍需实机测 RSS 和帧率。
- Transformer 深训、FP32/INT8 策略匹配、ROS2 消息契约、UART/CAN/J5 新鲜度和安全门回放均通过；量化包体按主文件加外置权重计算为 0.70/1.92 MB。硬件配置保持 `motion_enabled=false`。树莓派包 32 个文件，约 10.99 MB，预算估算 1280 MB/2048 MB。

## 小U呈现建议

1. 主画面固定为真实相机或仿真相机，叠加 YOLO 框、置信度、目标中心、`base_link` TF 和规划轨迹预览；不要用大面积装饰卡片挤占观察区。
2. 左侧只显示当前阶段：观察、准备、接近、抓取、抬升、放置或阻断。阻断状态必须显示具体原因，例如 `J5 数据年龄 820 ms`、`硬件未就绪` 或 `轨迹碰撞风险`。
3. 右侧显示六关节角度、在线状态、数据年龄、速度、扭矩和夹爪宽度；J5/J6 的数据年龄用独立警示色，不再只显示一个容易误解的 `online`。
4. 顶部用分段模式切换：仿真、只读硬件、低速实机。默认仿真；只读硬件只允许读 UART/CAN，低速实机需要 Pi、ROS2 和 F407 三层同时确认。
5. 执行前先展示目标姿态、抓取策略、夹爪宽度、预计时长、风险和轨迹；按钮先叫“预览轨迹”，确认后才出现“申请执行”。急停、暂停、重新检测、保存日志使用图标按钮并提供悬停说明。
6. 表情屏只反馈状态，不代替数字状态和错误原因。正常时克制，等待时显示关注，阻断时显示明确的警示；错误日志始终可导出 JSON。

## 硬件回来后的顺序

先运行 `hardware_return_preflight.py`，再断开电机动力做 UART PING、逐关节读取和 J5/J6 新鲜度采样；随后只读监听 CAN。确认急停、F407 校准记录 CRC、编码器方向和限位后，才做单轴低速、空夹爪、空载目标和低速实物回归。任何超时、CRC 错误、反馈年龄超阈值或碰撞风险都保持运动门关闭。
